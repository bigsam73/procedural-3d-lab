계산하는 3D와 저장하는 3D

같은 장면입니다. 사막 위에 금속 구 하나. 왼쪽은 데모씬 4k 인트로처럼 수식 몇 줄로 매 픽셀을 계산하고, 오른쪽은 게임 엔진처럼 미리 만들어 둔 정점 데이터를 읽어서 그립니다. 슬라이더를 움직이며 두 쪽의 숫자가 어떻게 다르게 변하는지 보세요. 화면을 끌면 카메라가 돕니다.

방식 A · 데모씬 인트로

장면을 계산한다 SDF + 레이마칭. 픽셀마다 "표면까지 거리" 함수를 수십 번 평가합니다.

–셰이더 소스 (장면 전체)
0 B정점 데이터
–매 프레임 계산하는 픽셀
–프레임 시간

장면 정의 map() — 직접 고쳐서 적용해 보세요

사용 가능: terrain(vec2) 사막 높이, sdBox, sdTorus, smin, uTime, uMelt. 반환값은 vec2(거리, 재질)이고 재질 1은 사막, 2는 금속입니다.

방식 B · 게임 엔진

장면을 저장한다 삼각형 메쉬 + 래스터라이즈. 파일에 든 정점을 GPU가 삼각형으로 투영합니다.

–정점·인덱스 데이터
–정점 수
–삼각형 수 · 드로우콜
–프레임 시간

자산 파일 내용 — 숫자 그 자체가 모양입니다


      
// 엔진 쪽 코드는 모양을 모릅니다. 파일을 읽어 놓기만 합니다.
const sphere  = loadMesh("sphere.bin");    // 정점·노멀·인덱스
const terrain = loadMesh("terrain.bin");   // 정점·노멀·색(베이크)
for (const pos of placements) draw(sphere, pos);
draw(terrain);

      
구의 반사에 사막이 비치지 않습니다. 메쉬 방식은 주변을 "알지" 못해서 하늘색 환경맵만 비춥니다. 왼쪽은 반사 광선을 한 번 더 전진시켜 실제 사막을 비춥니다.

    

  






  
이렇게 실험해 보세요

  
    
    
  1. 복제. 왼쪽에서 "무한 반복" 프리셋을 누르면 코드 한 줄이 추가되고 구가 무한히 늘어납니다. 프레임 시간은 거의 변하지 않습니다. 오른쪽에서 복제 개수를 10으로 올리면 100개가 그려지고 드로우콜과 정점 수가 100배가 됩니다.
    2. 
    
  2. 녹이기. 양쪽 슬라이더를 같이 올려 보세요. 왼쪽은 거리 함수에 사인 항 하나가 더해진 것뿐입니다. 오른쪽은 매 프레임 CPU가 정점 전부를 이동시켜 GPU로 다시 보냅니다. 구 세분화를 128로 올린 뒤 녹이면 CPU 시간이 눈에 띄게 늘어납니다.
    3. 
    
  3. 지형 수정. 거칠기를 바꿔 보세요. 왼쪽은 상수 하나가 바뀌어 즉시 반영됩니다. 오른쪽은 지형 자산을 다시 만들어야 해서 재생성 시간과 바뀐 파일 크기가 표시됩니다. 실제 파이프라인에서는 이 단계가 "모델러에게 요청 → 재익스포트 → 재임포트"입니다.
    4. 
    
  4. 비용의 축. 왼쪽에서 해상도 배율을 1.0으로 올리고 히트맵을 켜 보세요. 비용은 픽셀 수와 스텝 수에 비례하고, 물체 가장자리와 지평선 근처가 가장 비쌉니다. 오른쪽에서 지형 격자를 256으로 올리고 와이어프레임을 켜 보세요. 비용과 파일 크기는 삼각형 수에 비례합니다.
    5. 
    
  5. 형태의 자유. 왼쪽에서 "CSG 차집합"이나 "녹아 붙는 두 물체"를 누르면 상자에서 구를 빼내거나 두 물체가 녹아 붙는 형태가 한 줄로 나옵니다. 오른쪽에는 그 형태의 메쉬 파일이 없다는 안내가 뜹니다. 반대로 구에 로고를 새기고 싶다면 오른쪽은 텍스처 한 장이지만 왼쪽은 수식으로 표현할 방법이 없습니다.
    6. 
  






  
숫자가 말해 주는 것

  

  

    
관점계산 (왼쪽)저장 (오른쪽)

    
      
장면이 들어 있는 곳셰이더 텍스트 수 KB. 압축하면 수백 바이트정점 버퍼 수백 KB ~ MB. 실제 게임은 GB

      
비용이 비례하는 것픽셀 수 × 스텝 수. 장면이 복잡해져도 픽셀 수는 같다정점 수 × 드로우콜. 해상도를 올려도 정점 수는 같다

      
복제와 반복mod() 한 줄, 무한, 공짜인스턴싱으로 완화하지만 정점 처리와 드로우콜은 늘어난다

      
형태 변형수식에 항을 더한다. 모든 점이 동시에 바뀐다정점을 하나씩 옮긴다. 엔진은 버텍스 셰이더로 넘기는데, 그 순간 왼쪽 방식을 빌려오는 것이다

      
특정 부분만 수정어렵다. 수식은 "이 돌 하나"를 모른다쉽다. 그 정점만 움직이면 된다

      
비정형 형태 (얼굴, 로고, 손그림)거의 불가능본령. 아티스트가 무엇이든 만든다

      
반사, 충돌, 그림자거리 함수가 곧 공간 정보라서 자연스럽다별도 기법(환경맵, 콜라이더, 섀도맵)이 필요하다

      
만드는 사람수학을 쓰는 프로그래머 한두 명모델러, 텍스처, 리깅, 레벨 디자이너로 나뉜 팀

    
  

  

  
실제 산업은 둘을 섞습니다. 게임의 물, 구름, 불은 왼쪽 방식의 셰이더이고, No Man's Sky의 행성은 왼쪽 방식으로 만든 뒤 오른쪽 방식의 메쉬로 굽습니다. 데모씬 64k 팀도 자체 에디터로 노드를 조립해 실행 시 메쉬를 생성합니다. 어느 쪽이 맞는지는 "이 형태를 규칙으로 설명할 수 있는가" 한 가지로 갈립니다.
