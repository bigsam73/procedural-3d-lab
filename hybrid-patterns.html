하이브리드 파이프라인 실험실

실무에서 쓰는 방법은 "계산"과 "저장"을 역할로 나누는 것입니다. 네 개의 실험대마다 어느 부분을 계산하고 어느 부분을 저장했는지 띠로 표시했습니다. 슬라이더를 움직이며 비용과 용량이 어느 쪽에서 늘어나는지 보세요. 캔버스를 끌면 카메라가 돕니다.

계산 매 프레임 수식으로 베이크 한 번 계산해서 저장 데이터로 읽음
실험대 1 · 파이프라인의 뼈대

생성 → 베이크 → 저장: 지형 하이트맵

노이즈 생성기 (파라미터 4개)→ 베이크 버튼→ terrain.r16 하이트맵→ 에이전트가 높이를 읽음

슬라이더는 생성기의 파라미터입니다. "실시간 계산 미리보기"를 켜면 GPU가 매 프레임 노이즈를 다시 계산해 바로 보여 주지만, 베이크하기 전까지 에이전트들은 저장된 옛 지형 위를 걷습니다. 그래서 떠 있거나 땅에 묻힙니다. 저장이 결정적이어야 하는 이유입니다.

terrain.r16
–하이트맵 크기 (129×129×2 B)
–베이크 상태
–에이전트 높이 질의 (JS)
–GPU 시간
// 생성기 (오프라인 툴 또는 빌드 스크립트)
h(x,z) = fbm(x·f + seed, z·f + seed) · amp
// 베이크: 129×129 격자에서 한 번만 계산해 파일로
terrain.r16 = uint16[129*129]
// 런타임: 물리·AI·네트워크는 파일만 읽는다
y = heightmap.sample(x, z)   // 배열 4개 보간, 결정적
실험대 2 · 손으로 만든 자산을 규칙으로 뿌린다

규칙 배치 + GPU 인스턴싱: 바위 3,000개

바위 메쉬 4종 (손 모델링 역할)+ 배치 규칙 (경사·밀도·시드)→ 배치 배열 N × 24 B→ 인스턴싱 드로우 4회

바위 네 개만 아티스트가 만들고, 어디에 몇 개 놓을지는 규칙이 정합니다. 규칙을 바꾸면 수천 개가 즉시 재배치됩니다. 인스턴싱을 끄면 바위마다 드로우콜 하나가 되어 같은 그림에 비용만 수십 배가 됩니다.

–바위 메쉬 4종 합계
–인스턴스 수 · 배치 데이터
–드로우콜
–GPU 시간
// 배치 규칙: 바뀌면 전부 즉시 재배치
for each cell (x, z) with jitter:
  if slope(x,z) > minSlope && hash(x,z) < density:
    place(rock[hash2 % 4], scale 0.4~1.2, rotY)
// 결과는 배열로 저장. 엔진은 종류별로 한 번에 그린다
drawInstanced(rock[k], placements[k])   // ×4
실험대 3 · 패턴 1

메쉬는 저장, 변형은 계산: 풀 흔들기

풀잎 메쉬 N개 (정점 7개씩)+ 버텍스 셰이더 sin() 한 줄

풀 모양은 저장된 정점 그대로입니다. 바람에 흔드는 일만 계산합니다. 같은 계산을 CPU에서 하면 매 프레임 정점 전부를 JS가 옮기고 GPU로 다시 보내야 합니다. 풀 개수를 올리면서 두 모드를 비교해 보세요.

–정점 수 · 메쉬 데이터
–CPU 변형 시간 / 프레임
–GPU로 재전송 / 프레임
–GPU 시간
// 버텍스 셰이더: 저장된 정점 + 계산된 흔들림
vec3 p = aPos;                       // 파일에서 온 정점
float f = p.y / bladeHeight;
float sw = sin(uTime*2.0 + root.x*0.5 + root.z*0.3 + phase);
p.xz += uWind * f*f * sw * vec2(1.0, 0.3);
gl_Position = uVP * vec4(p, 1.0);
실험대 4 · 패턴 2

메쉬로 실루엣, 셰이더로 디테일: 바위 하나

저폴리 메쉬 320 삼각형+ 프래그먼트 셰이더가 노이즈로 울퉁불퉁함을 계산

같은 바위를 네 가지 방법으로 그립니다. 확대 슬라이더를 끝까지 올려 보세요. 노멀맵은 텍셀이 보이기 시작하고 고폴리는 용량이 수 MB이지만, 셰이더 디테일은 용량 0에 어느 거리에서도 선명합니다. 대신 매 픽셀 노이즈를 계산하는 비용을 냅니다.

–삼각형 · 메쉬 데이터
–텍스처 데이터
–디스크 합계
–GPU 시간
// D: 저장된 노멀을 계산된 기울기로 흔든다 (범프 매핑)
vec3 n = normalize(vNormal);          // 메쉬에서
vec3 g = grad(fbm3(p * uFreq));        // 노이즈 기울기
n = normalize(n - amp * (g - n * dot(g, n)));
// C는 같은 식을 한 번 계산해 텍스처에 굽고, 매 프레임 읽는다

결정 규칙 세 줄

  1. 규칙으로 설명되는가? 그러면 생성기를 짜라 (실험대 1, 2). 아니면 손으로 만들어 저장하라 (실험대 2의 바위 네 개).
  2. 다른 시스템이 그 값을 읽어야 하는가? 물리, AI, 네트워크가 쓰면 베이크해서 저장하라 (실험대 1의 에이전트). 눈에만 보이면 런타임에 계산해도 된다 (실험대 3의 풀, 실험대 4의 디테일).
  3. 매 프레임 바뀌는가? 그러면 저장할 수 없으니 GPU에서 계산하라. 단 CPU로 하지는 말라 (실험대 3).
